
**Дата:** 15 ноября 2026 г.

**Статус:** Принято

**Контекст:**

Для сервиса «Соберемся» необходимо выбрать инструменты автоматизированного тестирования.
Нам нужно гарантировать надежность ключевых сценариев: закрытая информация не видна посторонним (SEC04), лимит участников не превышается (FR11), скорость отклика соответствует PER01-PER04

**Рассмотренные варианты:**

1. **Ручное тестирование:** Проверка функционала разработчиками вручную без написания тестов
2. **BDD-стек - Gherkin:** Тестирование сценариев на естественном языке, легче делается на C#
3. **Go testing + testify / Vitest + RTL / Playwright:** Использование встроенных и бесплатных инструментов экосистем Go и TypeScript

**Решение:**

Выбран Go testing + testify / Vitest

**Обоснование:**

- **Нулевая стоимость:** Все инструменты распространяются по открытым бесплатным лицензиям (LIM06)
- **Соответствие стеку:** Тесты пишутся на Go и TypeScript, не требуя освоения сторонних языков или сложных DSL
- **Изоляция проверок:** testify позволяет быстро протестировать правила доступа и переходы статусов заявок без развертывания боевой БД

**Недостатки решения:**

- E2E-тесты медленные и хрупкие, поэтому покрывают только критичные сценарии
- Конкурентное одобрение заявок требует интеграционных тестов с реальной MySQL, что увеличивает время сборки

**Последствия:**

- Юнит-тесты станут обязательным условием прохождения CR
- Правила доступа к закрытой информации покрываются отдельными тестами для гостя, пользователя, заявителя, подтверждённого участника, организатора и модератора
- E2E-тесты будут покрывать только критические сквозные сценарии: поиск -> заявка -> одобрение -> обсуждение, жалоба -> решение модератора
