
**Дата:** 15 ноября 2026 г.

**Статус:** Принято

**Контекст:**

Нам нужна надежная база данных для проекта «Соберемся». Данные сильно связаны: пользователи, активности, заявки, отзывы, жалобы. Количество подтверждённых участников не должно превышать лимит при одновременном одобрении заявок (FR11), поэтому нужны транзакции. Данные должны храниться в РФ (SEC01)

**Рассмотренные варианты:**

1. **PostgreSQL:** Объектно-реляционная система управления базами данных
2. **MySQL:** Классическая реляционная БД с транзакциями, блокировками строк и полнотекстовым поиском.
3. **MongoDB:** Документоориентированная система управления базами данных.

**Решение:**

Выбран MySQL

**Обоснование:**

- MySQL прописана в разрешенном стеке технологий (LIM07)
- **Транзакции:** Блокировка строки активности (`SELECT ... FOR UPDATE`) при одобрении заявки гарантирует, что лимит участников не будет превышен
- **Реляционность:** Структура данных (пользователи, роли, активности, заявки, жалобы) сильно связана, реляционная модель здесь идеальна
- **Поиск:** Встроенный полнотекстовый индекс покрывает поиск активностей по названию (FR06) без отдельного поискового движка
- **Сообщество:** Большое и активное сообщество, множество доступных материалов

**Недостатки решения:**

- Полнотекстовый поиск MySQL не учитывает морфологию русского языка ("бег" не найдёт "бегом")
- Единый экземпляр MySQL для всех сервисов - единая точка отказа

**Последствия:**

- Все данные проекта будут храниться в MySQL, каждый сервис работает со своей схемой.
- Все даты хранятся в UTC.
- Ежедневное резервное копирование и двоичный журнал для выполнения DUR02-DUR03
