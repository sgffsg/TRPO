
**Дата:** 15 ноября 2026 г.

**Статус:** Принято

**Контекст:**

Пользователи «Соберемся» загружают три вида изображений: аватарка профиля (FR04), превью активности (FR08) и скриншоты или фотографии к жалобам (FR16). Фото профиля и превью видны всем, включая гостей, а вложения жалоб - только модераторам и администраторам. Необходимо обеспечить хранение файлов, серверную проверку формата и размера и удаление файлов вместе с учётной записью (FR05, LRC02). Решение должно соответствовать микросервисной архитектуре и учитывать ограниченные ресурсы проекта. Файлы должны размещаться у российского провайдера в регионе Россия (SEC01).

**Рассмотренные варианты:**

1. **Файловая система сервера:** Проста на старте, но усложняет совместный доступ к файлам при нескольких экземплярах сервиса.
2. **MySQL, поля BLOB:** Хранение файлов увеличивает размер БД, нагрузку на неё и объём резервных копий.
3. **Объектное хранилище российского провайдера:** Отделяет файлы от реляционных данных и предоставляет API для работы с ними. В качестве конкретного решения рассматривается Yandex Object Storage.

**Решение:**

Использовать **Yandex Object Storage** и отдельный сервис **filestorage** на Go для управления файлами.

- Файлы хранятся в Yandex Object Storage, а их метаданные в собственной схеме MySQL сервиса filestorage.
- Filestorage принимает изображения (JPEG, PNG до 5 МБ), проверяет фактический формат и размер, удаляет метаданные EXIF, загружает их в хранилище и возвращает `fileId`. Остальные сервисы сохраняют связи с этим идентификатором.
- Ключи доступа к Yandex Object Storage находятся только у filestorage.
- При удалении учётной записи аватарка профиля удаляется в течение 30 дней (LRC02).

**Обоснование:**

- Работа с файлами, их проверка и контроль доступа сосредоточены в одном сервисе.
- Хранилище и filestorage можно масштабировать отдельно от остальных сервисов.
- S3 API позволяет менять реализацию хранилища без изменения интерфейсов остальных сервисов.

**Недостатки решения:**

- Потребуется развёртывание и сопровождение дополнительного сервиса.
- Привязка к провайдеру, хранение файлов оплачивается отдельно, хоть и в небольшом объёме.
- Вложения жалоб могут содержать персональные данные третьих лиц (скриншоты переписок), поэтому требуют такого же уровня защиты, как сообщения обсуждений.

**Последствия:**

- Для частично выполненных загрузок и неудачных удалений нужны повторные попытки и очистка лишних файлов.
- Хранилище включается в ежедневное резервное копирование (DUR02).
- Для одной жалобы допускается не более 5 вложений.
